# 本地化资源契约审查台（Localization Resource Contract Reviewer）

本地运行的 Web 应用，用于审查多语言 JSON/ARB 资源的 **ICU MessageFormat 契约一致性**
与 **显式父语言回退图**，并提供按语言渲染的**消息实例预览**。
技术栈：Python · FastAPI · SQLite · Babel（CLDR 复数/数字/日期）·
原生 JavaScript（无前端构建）。

## 功能

- **导入多语言资源**：多文件上传 `.json` / `.arb`，可嵌套对象（以 `.` 展平）。
  - ARB 元数据：自动跳过 `@key` 描述键；支持 `@@locale`、`@@parent` 约定；
  - 也可在表单中手工指定「文件名→语言」与「语言→父语言」（手工优先级更高）。
- **ICU MessageFormat 解析**（内置零依赖解析器）：
  - 简单占位符 `{name}`、带类型 `{count, number}` / `{d, date, medium}`；
  - `plural` / `select` / `selectordinal` 分支、嵌套占位符、`#` 数量符号、引号转义；
  - 跨语言引用键约定 `{@some.key}`（可指向嵌套键，沿回退链解析）。
- **契约检测**：
  - 缺失键（父链可回退时降级为警告，建议值取自最近祖先）；
  - 多余键（基准语言之外的键，警告）；
  - 占位符缺失 / 多余 / 类型不一致（含分支体内的嵌套占位符、引用键集合差异）；
  - 分支不一致：`select` 标签必须精确一致；`plural/selectordinal` 译文必须覆盖
    基准的全部标签（允许译文新增 `=N` 与细粒度 CLDR 标签）；基准复数必须有 `other`；
  - ICU 语法错误（携带字符位置）；
  - 引用键沿父链无法解析；
  - 回退图：循环回退、父语言未导入导致链中断、链未到达基准语言（未覆盖语言）。
- **稳定排序与确定性输出**：问题按 `(语言, 键, 字符位置, 类型, 区分尾键)` 排序；
  版本号由规范化输入的 SHA-256 导出，相同输入导入为幂等操作。
- **确定性修复建议**：
  - `upsert`：缺失/占位符/语法问题给出草稿值（继承值或基准文案），标记为需人工复核；
  - `delete`：多余键、非字符串资源值；
  - `text_patch`：基于解析位置的精确文本补丁（自动补/删分支、基准补 `other`），
    补丁后强制重新解析校验；
  - `set_parent`：打破循环 / 修复未覆盖语言。
- **差异报告**：任意两个版本之间按语言、键列出新增 / 删除 / 修改及语言集合变化。
- **引用影响分析（⑥）**：选择不可变版本、语言与消息键后：
  - 解析消息中的 ICU 跨语言引用 `{@key}`，沿**显式父语言链**解析落点
    （本语言优先、逐级向上），构建跨语言引用依赖图；
  - 计算删除 / 改写该键的**传递影响范围**：距离 1 为直接依赖、
    距离 ≥2 为间接依赖；受影响节点按 `(距离, 语言, 键)` 稳定排序；
  - 每条受影响消息给出 BFS **最短证据路径**（节点链 + 逐跳引用键 + 消息值，
    可在页面展开），并列出受影响语言集合；
  - Kosaraju 求强连通分量，报告**循环 SCC**（含自环）并标出目标是否在环内；
  - SVG 图谱支持子图 / 语言 / 断裂边筛选、节点点击查看出入边；结果可 **JSON 导出**；
  - 结果绑定**版本摘要**（rev、基准语言、current_rev）：分析的版本不再是当前
    版本时页面明确提示「结果已过期」（快照不可变，仍可查阅）；
  - **修复集影响预演（不落库）**：对 `delete/upsert/text_patch/set_parent`
    修复集在内存物化并重建引用图，按「边是否存在 × 是否可解析」区分：
    **新增断裂引用**（修复集引入：目标被删、回退链变化，或改写新引入的
    `{@key}` 本就解析不到）、**原有断裂引用**（修复前就存在）、顺带修复、
    改写后不再携带的断裂引用（源消息仍在）、落点随回退链变化（如遮蔽键被删
    后改由祖先承接）、随源消息删除消失的引用，并给出预演后的传递影响。
- **乐观并发的原子合并**：仅当审查所基于的版本仍是当前版本时才合并，否则返回 `409`；
  修复集内任一项无效则整体不落库；合并产生**新版本**（旧版本与审计永久保留）。
  基线复核、新快照写入、合并审计与 `current_rev` 切换共享同一个 SQLite 写事务
  （`BEGIN IMMEDIATE`）：任一步失败整体回滚，不留部分状态；并发的同基线合并在
  写锁内串行，事务内重新核对基线，因此同一 `base_rev` 只有一个合并能成功，
  陈旧结果不会覆盖当前指针。
- **审计记录**：导入、合并的操作者、来源/目标版本、审查基线与逐项操作明细。
- **消息实例预览（⑦，只读）**：选择不可变版本、一个或多个目标语言与消息键，
  填入同一组变量 JSON 后并排渲染最终文本：
  - 消息先沿每个目标语言的**显式父语言链**解析到实际文案（本语言优先、逐级
    向上），标注「实际取值语言」「是否回退」及走过的回退链；
  - 引用 `{@key}` 从**所在消息的语言**继续沿其父链解析（近遮蔽优先），
    返回按求值顺序排列的**引用轨迹**（逐跳：源 → 落点、各自的回退链）；
  - 数字 / 日期 / 时间与复数、序数按**目标语言**处理（Babel + CLDR）：
    number 支持命名样式与 LDML 模式、`::currency/USD`、percent 等；
    `plural` / `selectordinal` 借助 CLDR 规则选择分支，**精确数值分支
    `=N` 优先**，其次 CLDR 类别，缺省走 `other`；`#` 数量符号按目标语言
    默认十进制格式输出（嵌套复数时取最内层参数）；
  - 日期时间参数使用 **ISO 8601 字符串**
    （如 `2026-03-09`、`2026-03-09T13:05:07`、`13:05`）；
  - 缺少参数、类型不符、无可用分支、断裂引用、引用环、被引用消息语法错误等
    情况，出错语言返回携带**语言、键与结构化路径**的错误对象，**不输出任何
    部分文本**；其余语言照常预览；
  - 预览完全**只读**（不写快照、不写审计、不切换当前版本），结果绑定所选
    版本；所选版本不再是当前版本时页面显示「结果已过期」横幅（快照不可变，
    仍可查阅）。
- **自包含语言包编译（⑧，只读）**：选择不可变版本、目标语言集合与入口键集合，
  生成可直接交付的 ZIP 语言包：
  - 每个入口键先沿目标语言的**显式父语言链**确定实际来源（本语言优先、逐级
    向上）；消息内的 `{@key}` 从**引用所在消息的语言**继续沿其父链递归解析
    （近遮蔽优先），被引用消息**就地展开**——导出的 JSON 不再含任何 `{@key}`，
    消费方**无需原数据库、无需父链**即可使用；
  - 展开保留完整 ICU 语义：变量（含 number/date/time 类型与样式）、
    `plural` / `select` / `selectordinal` 分支与嵌套占位符；被引用消息顶层
    的 `#` 内联进复数上下文时自动加引号保持字面量语义，而其自身复数分支内的
    `#` 始终绑定最内层参数；单引号转义按 ICU 规则重新编码；
  - **断裂引用、引用环、入口不可解析、目标语言不存在、语法错误都会阻止整包
    生成**（不输出任何文件字节），错误携带**语言、入口键与结构化引用路径**
    （`@key` 序列及回退链/环），一次编译的全部错误稳定排序后一起返回；
  - 成功时按**稳定键序**为每个语言生成 `<locale>.json` 与 `manifest.json`
    （清单含清单版本、版本摘要 rev/基准语言/input_hash/创建时间、语言与键集合、
    **逐键来源**（实际来源语言/是否回退/回退链、展开涉及的全部消息来源、逐跳
    引用轨迹）、每个文件的字节数与 **SHA-256**、ZIP 字节数与 SHA-256）；
  - **确定性**：JSON 以排序键 + 两格缩进 + 行尾换行规范化，ZIP 条目按路径排序、
    固定时间戳/权限，相同输入（同一版本 + 相同语言与键集合，顺序/重复无关）
    重复编译得到**逐字节相同**的包；
  - 页面提供 **ZIP 下载**（GET 直链）与**逐键来源查看**（实际来源、回退链、
    引用展开轨迹与展开后的自包含模板）；编译**只读**，不改写资源版本、
    不写审计、不切换当前版本；结果绑定版本快照，版本过期时页面显示横幅。
- **资源键重命名迁移（⑨）**：选择不可变版本并提交有序 `old_key→new_key` 映射，
  把资源键与消息中的 ICU 引用在**一个事务**内同步改名：
  - 提交前一次性聚合校验（结构化错误、稳定排序）：源键必须在资源键空间存在
    （任一语言拥有，含非字符串叶子）；目标键不得与**未迁移键**冲突
    （否则同语言撞键或改变近遮蔽回退落点）；映射一对一（源、目标均不可重复，
    完全相同的映射对按提交顺序去重）；**禁止链式歧义**（拒绝 `a→b,b→c` 与
    `a→b,b→a` 之类的链/环，引用只允许一跳到位）；目标键字符必须可作为
    `{@key}` 引用名（字母、数字、`.`、`_`、`-`）；
  - 引用改写严格按**每条引用所在语言的显式回退链**解析（本语言优先、逐级
    向上，与影响分析/预览/语言包编译同一规则）：如某语言自身遮蔽了某键时
    `{@key}` 改写到该语言的新键，子语言缺失该键时沿父链改写到祖先的新键；
    回退遮蔽保证改名后引用仍解析到同一条消息，**不引入新的断裂引用**；
  - **试运行不写库**：按语言、键、字符位置稳定排序返回完整改写计划——
    键改名清单（命中语言与回退缺失语言）、逐条引用改写（区间、新旧键、
    解析落点与回退链）、断裂风险（**原有断裂引用**保持原文不改、**ICU 语法
    错误消息**中的引用仅 best-effort 告警不改写、物化后若出现**新增断裂**
    则 fail-closed 列出），并附确定性 16 位计划摘要（与提交顺序无关）；
  - **确认**携带试运行时的 `expected_rev`：仅当它仍是当前版本才执行新迁移，
    否则 `409`；基线复核、新快照写入、`rename` 审计、完成记录与
    `current_rev` 切换共享同一个 `BEGIN IMMEDIATE` 事务，任一步失败
    （含故障注入）整体回滚；旧版本永久保留，产物为新不可变版本；
  - **重试幂等**：已完成迁移按 **（源版本 rev，规范化计划摘要）** 识别。
    首次确认把 `current_rev` 推进到新版本后，客户端用**原 rev、原
    expected_rev、同一映射**（提交顺序无关）重试时，不会再得到 409：
    接口在事务内核对产物版本与原始 `rename` 审计关系一致后**回放**首次
    结果（200、`replayed=true`），返回相同的新旧版本与变更清单，
    **不新建版本、不追加审计、不切换当前指针**；尚无成功记录的过期请求
    仍返回 `409`；失败事务整体回滚、不会留下可被误认作已完成的记录；
    `(base_rev, plan_hash)` 主键保证并发重复提交只有一次真正生效；
  - **旧数据卷升级恢复**：使用旧版本镜像写入的 Docker volume 中只有
    `rename` 审计（源/目标版本、基线、`detail.plan_hash` 与映射）和产物
    版本，没有 `rename_record` 完成关系表（升级后 `init_db` 只建空表）。
    应用启动建表后会在**事务**内按（源版本, 计划摘要）从历史审计恢复
    已完成关系：核对源版本、产物摘要（对源快照按审计映射重算试运行与
    物化，比对产物 `input_hash`）以及审计的源/目标/基线与计划摘要；
    同源同计划的重复审计只有关联（目标版本、映射集合）一致才归并，
    冲突或残缺（缺映射/计划摘要、产物缺失或摘要不符）的组**明确拒绝
    回放**（启动日志列出拒绝明细，确认接口返回 500），不登记、不覆盖
    已有有效记录；确认链路自身也会在事务内按需恢复，因此未重启时的
    过期重试同样回放首次结果。恢复全程**不新增版本或审计、不切换
    当前指针**，重复升级幂等，并发恢复只登记一次；
  - 结果包含**新旧版本号**（`from_rev/new_rev`）与**变更清单**（键改名、
    按消息去重的值改写 from→to）；页面提供**试运行、确认、JSON 下载**，
    版本过期时显示横幅（确认会以 409 拒绝，需重新试运行）。

## 一键启动（Docker Compose）

```bash
docker compose up --build
```

启动后访问：

- 应用界面：<http://localhost:8000/>
- API 文档（Swagger）：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/api/health>

语言包编译模块（⑧）随应用一并启动，无需额外服务或卷；编译完全在内存中进行
（不写库），打开 <http://localhost:8000/> 切换到「⑧ 语言包编译」即可使用。

资源键重命名迁移模块（⑨）同样随应用一并启动，无需额外服务或卷；试运行在
内存中完成（不写库），打开 <http://localhost:8000/> 切换到「⑨ 键重命名迁移」
即可使用。

数据保存在 Docker volume `lrc-data` 中的 SQLite 数据库（`/data/lrc.db`）。
停止后数据保留；如需清空：`docker compose down -v`。

升级到新版本镜像后直接 `docker compose up --build` 即可：应用启动时自动
建表/迁移并在事务内恢复旧卷中已完成的重命名关系（见「⑨」的旧数据卷升级
恢复说明），无需手工干预；若发现无法核对的残缺/冲突关系，启动日志会列出
拒绝明细（不影响其他数据与功能，相关重试会明确报错而不是返回错误结果）。

端口可在 `docker-compose.yml` 中修改（左侧宿主机端口）。

## 本地直接运行（不使用 Docker）

需要 Python 3.11+：

```bash
pip install -r requirements.txt
export LRC_DB_PATH=./data/lrc.db
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 快速试用

`samples/` 下提供 4 个故意带问题的示例文件（en 基准，fr/de/ja）。

1. 打开 <http://localhost:8000/>，在「① 导入资源」中选择 `samples/en.json`、
   `fr.json`、`de.json`、`ja.json`；
2. 基准语言填 `en`（文件内已含 `@@parent`，也可在「显式父语言链」中填
   `{"fr":"en","de":"en","ja":"en"}`）；
3. 导入后在「② 问题清单」查看：缺失键、占位符不一致（如 ja 的 `{user}` vs `{name}`、
   de 的价格类型）、分支缺失（de 缺 `female`）、断裂引用（ja 的 `{@does.not.exist}`）等；
4. 勾选修复（标注「可自动应用」的为结构性安全补丁，其余建议人工复核），点击
   「原子合并所选修复」生成新版本；
5. 在「③ 回退图」查看语言→父语言链与覆盖状态；「④ 差异报告」对比两个版本；
   「⑤ 审计记录」查看操作历史。
6. 在「⑥ 引用影响」中选择版本、语言（如 `en`）与消息键（如 `appTitle`），
   点击「分析影响」：
   - 示例数据中 `en.refA → en.appTitle`、`en.refB → en.refA`、
     `de.refC → en.refA`（de 无 refA，沿 de→en 回退）、
     `ja.jaGuide → en.refB`（沿 ja→en 回退），因此 `en.appTitle` 有
     1 个直接依赖、3 个间接依赖，最短证据路径
     （如 `ja:jaGuide ▶ en:refB ▶ en:refA ▶ en:appTitle`）可逐行展开；
   - 注意 `fr.refA → {@appTitle}` 解析到 **fr 自己的 appTitle**
     （本语言优先于父链的遮蔽语义），故它不在 `en.appTitle` 的影响集中；
   - `cycX ↔ cycY` 互相引用，会被报告为循环强连通分量；
     `ja.brokenRefDemo → {@does.not.exist}` 作为原有断裂引用单独列出；
   - 在下方「修复集影响预演」点击「＋ 删除该键」→「运行预演」，可看到
     en 的 `refA` 引用变为**新增断裂**（原因 target_deleted），而 ja 的
     `does.not.exist` 仍归类为**原有断裂**；整个预演不写库、不产生新版本；
   - 若之后通过「原子合并」产生了新版本，回到旧版本的分析结果时页面会显示
     黄色「结果已过期」横幅（15 秒轮询 `/api/state` 自动刷新该状态）；
   - 「导出 JSON」下载包含版本摘要、图谱、证据路径、SCC、断裂引用及最近一次
     预演结果的完整 JSON。
7. 在「⑦ 消息预览」中选择版本、目标语言（可多选，默认全选）与消息键，填入
   变量 JSON（如 `{"name":"Ana","count":2}`），点击「生成预览」：
   - 选择 `cart.items` 与变量 `{"count":0}`：en 取精确分支 `=0`，
     fr/de/ja 分别按各自 CLDR 规则渲染，`#` 按语言本地化；`count=1.5` 时
     可看到 fr 的法语复数规则与 de/en 的差异；
   - 选择 `greeting` 与 `{"name":"Ana"}`：en/fr/de 正常，ja 因占位符为
     `{user}` 而返回 `MISSING_PARAM` 结构化错误（仅该语言不出文本）；
   - 选择 `refB`（ja 无该键）可看到消息回退到 `en`，引用轨迹
     `en:refB → en:refA → en:appTitle`；选择 `fr.frNote` 可看到
     `{@untranslatedNote}` 从 fr 沿链落到 en；
   - `cycX` 返回 `REFERENCE_CYCLE`、`ja.brokenRefDemo` 返回
     `BROKEN_REFERENCE`（均带路径与回退链）；
   - 日期类键（如 `event_notice`）变量形如
     `{"eventDate":"2026-03-09T13:05:07","name":"Ana"}`，日期按各语言
     格式渲染。
8. 在「⑧ 语言包编译」中选择版本、目标语言（如 `fr`、`de`）与入口键
   （如 `appTitle`、`refA`、`greeting`），点击「编译语言包」：
   - `fr.refA` 中的 `{@appTitle}` 就地展开为 **fr 自己**的标题（遮蔽语义）；
     `de` 没有 `refA`，该键沿 `de→en` 回退，来源标记为「回退取值」，
     其内的 `{@appTitle}` 继续从 `en` 解析；
   - 成功后点击「⬇ 下载 ZIP 语言包」，内含 `fr.json`、`de.json` 与
     `manifest.json`（逐键来源与文件 SHA-256），再次编译/下载得到相同字节；
   - 选择 `ja` + `brokenRefDemo`（或 `cycX`）编译会**整包失败**，表格列出
     语言、入口键、引用路径（`@does.not.exist`）与回退链；
   - 只选 `ja` + `jaGuide` 可得到完全自包含的 `ja.json`：其值
     `ご案内：…` 已内联 `en.refB → en.refA → en.appTitle`，把该 JSON 作为
     无父链的新资源导入后即可独立使用。
9. 在「⑨ 键重命名迁移」中选择版本，在映射表填入
   `appTitle → app.title`、`refA → ref.a`、`refB → ref.b`（也可用
   「从 JSON 载入」粘贴 `[{"old_key":"appTitle","new_key":"app.title"}]`），
   点击「试运行（不写库）」：
   - 键改名清单显示 `appTitle` 命中 en/fr/de/ja，`refB` 仅命中 en（ja 等
     语言列入「缺失语言」，回退不产生条目）；引用改写表按语言/键/位置排序：
     `fr.refA` 中的 `{@appTitle}` 解析落点为 **fr 自己**（遮蔽语义），
     `de.refC` 的 `{@refA}` 沿 `de→en` 落到 **en.refA**，
     `ja.jaGuide` 的 `{@refB}` 沿 `ja→en` 落到 **en.refB**；
   - 风险区列出 `ja.brokenRefDemo` 的**原有断裂引用** `{@does.not.exist}`
     （保持原文，不会被改写），断裂引用计数迁移前后不变；
   - 点击「确认迁移（新版本）」生成新版本：新键 `app.title/ref.a/ref.b`
     与全部 `{@key}` 引用同步改名，旧版本与 `rename` 审计保留；
     首次确认后用原 rev、原 `expected_rev` 与同一映射重试会**回放**首次
     结果（`replayed=true`，不新增版本/审计、不切换指针），而不是 409；
   - 尝试 `refA → refB, refB → refB2` 会被「链式歧义」拒绝；
     `refB → greeting` 会被「目标键与未迁移键冲突」拒绝；
     试运行后若他人先合并了新版本，确认会返回 `409`，需重新试运行；
   - 「⬇ 下载结果 JSON」可保存完整计划 / 确认结果（计划摘要、改写清单、
     风险、新旧版本与变更清单）。

## API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/import` | multipart 上传文件（`base_locale`、`parents_json`、`locales_json`） |
| POST | `/api/import-json` | 等价的 JSON 接口，便于脚本调用 |
| GET | `/api/revisions` | 版本列表（含当前标记） |
| GET | `/api/revisions/{rev}` | 版本元信息与语言清单 |
| GET | `/api/revisions/{rev}/issues` | 问题清单，可按 `severity/code/locale` 过滤 |
| GET | `/api/revisions/{rev}/graph` | 回退图节点、链与状态、循环 |
| GET | `/api/revisions/{rev}/impact?locale=&key=` | 引用依赖图、传递影响、最短证据路径、循环 SCC |
| POST | `/api/revisions/{rev}/impact/preview` | 修复集不落库影响预演（新增/原有/移除/修复的断裂引用分类） |
| POST | `/api/revisions/{rev}/preview` | 消息实例只读预览（`{key, locales[], variables{}}`，逐语言返回文本/回退/引用轨迹或结构化错误） |
| POST | `/api/revisions/{rev}/pack` | 编译自包含语言包（`{locales[], keys[]}`）：模板/逐键来源/清单/SHA-256；整包被错误阻止时返回 422 |
| GET | `/api/revisions/{rev}/pack/download` | 同上的确定性 ZIP 下载（`locales`/`keys` 可重复查询参数） |
| POST | `/api/revisions/{rev}/rename/plan` | 键重命名试运行（`{mappings:[{old_key,new_key}]}`）：改写计划/引用/风险，不写库；校验失败 400 |
| POST | `/api/revisions/{rev}/rename/commit` | 确认迁移（`{expected_rev,mappings,actor}`）：单事务生成新版本与审计；按（源版本,计划摘要）回放已完成迁移（200 `replayed=true`，无写入），无成功记录的过期请求 409；旧卷升级在启动/确认从事务内按历史审计恢复，审计关系残缺或冲突时 500 拒绝回放 |
| GET | `/api/revisions/{rev}/entries/{locale}` | 某语言键值（可选 `?key=`） |
| GET | `/api/diff?from_rev=&to_rev=` | 两版本差异报告 |
| POST | `/api/merge` | 原子合并修复（`base_rev` 过期返回 409） |
| GET | `/api/audit` | 审计记录 |

## 约定与边界

- 回退遵循**显式**父语言链：未声明父语言的非基准语言会被报告为「未到达基准」，
  系统不做隐式区域推断（如 `fr_CA→fr` 必须显式声明）。
- 复数分支允许译文比基准更细（语言间 CLDR 类别差异），但基准声明的标签必须全部覆盖。
- `text_patch` 应用后必须仍是合法 ICU 消息，否则整个合并被拒绝（原子性）。
- 所有时间戳为 UTC；快照内容不可变，修复永远产生新版本。
- `{@key}` 引用按**本语言 → 父链逐级**顺序解析到首个拥有该键的语言（近遮蔽优先），
  因此同一引用键在不同语言可能落到不同目标；影响分析与断裂引用检测共用该规则。
- 预览渲染按目标语言选择 CLDR 复数/序数类别（Babel），精确分支 `=N` 优先；
  number/date/time 全部按目标语言格式化；预览为只读，错误逐语言隔离、
  不产生部分文本。
- 语言包编译为**只读 + fail-closed**：断裂引用、引用环、入口/被引用消息语法
  错误、入口沿链不可解析都会阻止整包（无部分文件），错误携带语言、入口键与
  `@key` 引用路径；展开后的模板无任何 `{@key}`，可脱离数据库与父链独立使用。
- 语言包编译是确定性的：输出只依赖（版本快照、语言集合、键集合），语言与键
  内部去重排序，JSON/ZIP 元数据全部固定；相同输入的 SHA-256 相同。
- 键重命名迁移作用于**全局键空间**（所有语言包中的同名键，含非字符串 invalid
  叶子）；某语言缺失该键是正常回退现象，不产生条目也不算风险。目标键不得与
  未迁移键冲突，映射必须一对一且无链/环；引用只按其**所在语言的回退链**
  一跳改写，原本断裂的引用与语法错误消息中的引用一律保留原文并在计划中标注
  风险。试运行只读；确认以 `expected_rev` 做乐观并发，单事务整体提交或回滚。
  已完成迁移按（源版本, 规范化计划摘要）识别：首次确认推进版本后，用原 rev、
  原 `expected_rev` 与同一映射重试会在事务内核对产物与审计关系后回放首次结果
  （不新建版本、不追加审计、不切换指针）；无成功记录的过期请求仍为 409；
  失败事务不留完成记录，并发重复提交只有一次生效。旧数据卷升级（只有 rename
  审计与产物、没有 `rename_record`）在启动建表后从事务内按历史审计核对恢复，
  核对源版本、产物摘要、审计的源/目标/基线与计划摘要；同源同计划的重复审计
  关联一致才归并，冲突或残缺明确拒绝回放（500）且不覆盖已有有效记录；
  重复升级与并发恢复幂等。
